# teco-target-customer-analyse

将目标客户的公开信息转化为合作判断、需求验证问题与销售行动。适用于跨行业B2B客户研究、关键角色分析及客户开发准备。

## 分析的目标

研究最终应回答四个问题：是否值得跟进、从哪里切入、接下来验证什么、采取什么行动。报告不以信息数量为目标，也不把公开信息推测当成客户的真实采购需求。

完整路径为：确认目标和我方背景 → 核实主体并收集证据 → 建立七维商业画像 → 形成合作与需求假设 → 设计验证问题 → 选择切入方式 → 根据新证据更新行动。

保留三个执行阶段：阶段1主体与商业风险核查，阶段2商业假设与关键人沟通，阶段3切入方案。研究时先收证据、后写结论；最终报告把销售行动摘要放在最前。

## 使用与输入

```text
$teco-target-customer-analyse
目标：真实公司全称、国家或官网URL
我方产品：实际产品简介、规格与已确认的供货能力
已有材料：客户询盘或经授权提供的沟通记录（可选）
本次目标：判断合作潜力并准备首次接触
风险偏好：中性
请完成三个阶段，输出七维商业画像、需求验证清单和销售行动摘要。
```

默认中文、连续完成三个阶段，风险偏好未提供时按中性注明。需要分步时写“仅阶段1”，随后发送“下一步”继续阶段2–3。阶段1的摘要只是初步判断。

最小输入是公司名称或官网。缺少国家或主体有歧义时先检索消歧；必要时询问一个识别问题。缺少我方资料时仍可研究客户，但不能虚构我方能力、产品匹配或合作价值。无法确认的信息写“待确认”，并说明需获证信息、目的和获取路径。

这是AI助手工作指令，不自带征信、海关或制裁数据库。实际公开核验需要可用的搜索和网页阅读工具；无联网能力时只能分析提供的材料。AWB（Accio Work）等平台是否能直接加载Skill，应以实际版本支持情况为准，不因提供了这份文件就宣称已完成集成。

## 阶段1 主体与商业风险核查

### 先锁定主体

核实公司法律名称、注册地、登记状态、官网和业务角色，区分品牌、母公司、子公司及实际合同主体。将登记资料、网站法律声明、联系方式等交叉匹配，不合并同名企业。优先使用已获得且仍有效的证据，按缺口补充检索。

经营真实性、财务履约、适用的交易限制及风险事件仍按SKILL.md和证据规则核查。未发现负面不等于没有风险，网站精美或成立时间长不等于具备偿付能力。

### 七维客户商业画像

| 维度 | 研究内容 | 对应销售判断 | 需要避免的误判 |
| --- | --- | --- | --- |
| 1. 公司规模与经营成熟度 | 经营年限、规模代理、组织职能、产品管理、渠道建设及供应商协作流程 | 与我方供货和服务能力是否匹配，需要何种支持 | 员工数推算采购量；大公司自动优先；成熟度等同信用 |
| 2. 产品线结构与我方切入点 | 核心和辅助品类、产品组合、规格配置梯度、自有品牌、新品变化 | 可否补充品类、升级配置、配套供应或提供替代方案 | 官网没有展示即认定缺货或需求；空缺即商机 |
| 3. 市场定位与价格带 | 目标客群、价值主张、档次、竞争对象及可比产品价格 | 应推荐哪类产品与价值方案 | 零售价直接换算采购价、预算或利润 |
| 4. 渠道布局与交付要求 | 自营、平台、门店、分销，以及已披露的包装、补货、交付与售后要求 | 客户销售方式可能要求怎样的供应支持 | 多渠道直接推断库存或包装管理有问题 |
| 5. 采购信号与合作时机 | 询价、供应商招募、新品、新市场、新渠道等变化 | 为什么现在联系，适合首次采购、补充、备用还是替换切入 | 扩张即采购；新品即换供应商；旧新闻仍是当前窗口 |
| 6. 合作要求与风险核查 | 合作准入、样品、验收、产品与市场要求；主体、付款、履约与交易风险 | 是否能满足条件，哪些核实工作影响交易推进 | 无关认证当必需；无负面当信用良好 |
| 7. 决策链与关键角色 | 需求提出、技术/产品评估、采购执行、财务审核、批准及内部推动角色 | 联系谁，帮助谁准备什么材料 | 职位等于最终签字权；强行补全未知角色 |

各维度统一记录：

| 已知事实及来源/日期 | 销售含义或需求假设 | 我方已证实能力与匹配缺口 | 待验证问题 | 下一步动作 |
| --- | --- | --- | --- | --- |
| 填写实际查到的信息 | 标明推测及其依据 | 只使用真实资料 | 写能改变销售决策的问题 | 明确要补资料、接触谁或暂缓什么 |

规模与经营成熟度分开观察。规模适配、需求匹配和进入难度共同影响开发优先级，不按人数或营收简单排序。

价格记录保留规格、数量（如可得）、币种、日期、渠道和促销/税运条件；条件未知时明确标记，无法比较的价格不强作高低结论。

采购信号分为直接、间接和背景三类。直接信号包括明确询价或供应商招募；间接信号包括新品或渠道扩展；背景包括一般宣传和历史经营方向。记录事件时间、发布日期及当前有效状态，信号强弱不等同成交概率。

研究深度以客户实际角色和采购方式为准。常规采购看选品、补货与售后；定制采购看规格、样品和变更；项目采购才核对立项、采购与实施阶段。不适用项说明原因，不扣分，也不当作缺失。

### 风险与机会分开呈现

合作要求回答“合作需要满足什么”；风险核查回答“哪些事实或未知项可能影响合作”。先确认适用性，再核对证据。身份冲突或疑似名单命中需人工核查，不得被其他有利信息抵消，也不能在消歧前认定违规。

保留现有业务30、财务履约30、合规交易40的研究辅助评分，不为七个维度另设平均分。未知不记零，不把已评部分外推成完整总分。开发星级与信用分开，不由总分自动换算。具体公式及判断条件以 [assessment.md](references/assessment.md) 为准。

## 阶段2 商业假设与关键人沟通

### 从事实形成待验证假设

每个重要推断都应沿着“已观察信号 → 可能的业务影响 → 需要验证的问题”展开。潜在痛点最多3项，不为凑数虚构困难。宏观变化只有能说明目标业务暴露时才与其关联。

例如，客户官网发布新系列，可以形成“可能有配套或后续扩品机会”的假设；不能据此写成“客户对现供应商不满意”。这是假设设计示例，不是真实客户研究结论。

### 优先需求验证清单

从全部未知项中选最多3个最影响跟进、推荐方案或推进时机的问题。优先问行动影响大、证据不足且客户能够回答的事项，不把全部研究缺口一次性发给客户。

| 验证问题 | 对应事实/假设与来源 | 为什么要问 | 适合询问的角色 | 不同答复如何改变行动 |
| --- | --- | --- | --- | --- |
| 示例：新系列是否还有配套产品计划？ | 已核实新品发布；扩品需求未确认 | 判断产品切入点是否成立 | 产品或品类负责人，职责待核实 | 有计划则澄清规格；暂无计划则不继续强推该方案 |
| 示例：新供应商评估最先需要什么材料？ | 已确认愿意评估，具体流程未知 | 确定下一份资料 | 采购或评估角色 | 按其要求准备现有真实材料；没有材料的项目标待准备 |
| 示例：适合在哪个节点重新讨论？ | 客户明确表示项目推迟 | 确定联系时机 | 当前联系人 | 约定节点再联系；未明确时保留未知，不自行判断预算已取消 |

实际问题应按个案选择，避免机械套用示例。客户未回复不是需求被否定或确认；一次答复只支持其对应范围。新答复进入记录时保留来源、日期、冲突及仍未确认的部分。

### 关键角色与沟通方式

先核实职业身份，再判断其可能参与的采购环节；角色可以重合，不要求每个客户有完整部门。建立“角色—已知职责—待确认权限—需要的材料”关系，帮助联系人内部推动。

个人沟通偏好只能依据可归属本人的职业行为或授权沟通记录，并列替代解释。只有职位信息时，提供岗位常见关注点，不生成此人的人格结论。DISC仍为可选、低置信度层，不参与信用与合规评分；具体证据门槛保持assessment.md规则。

## 阶段3 切入方案

按“客户业务信号 → 可能问题 → 我方已证实能力 → 对客户业务的意义 → 支持证据 → 下一步”组织方案。

明确适合接触的角色、我方切入身份、价值假设及支持材料。提供3条开发信首句和一个低压力CTA；没有可核实近期动态时，用真实业务事实或明确问题开场。不能承诺不存在的测试、案例或报告，未完成资料标待制作。只起草，不发送、不自动添加好友。

给优先验证问题配套条件式行动：

- 客户确认需求：澄清用途、规格或采购条件，再准备相应方案或样品安排。
- 客户认可方向但时间未定：核实项目节点与合适的再次联系时间。
- 客户明确不匹配：暂缓或停止该方向投入，不强行寻找话术突破。
- 客户尚未回复：保留未知，根据既有联系安排、相关新证据或低频维护条件决定后续。

上述分支只是计划，不自动执行外部动作。不要因一次没有回复而给客户降信用等级。

## 最终报告与销售行动摘要

报告默认在对话交付，顺序如下：

1. 销售行动摘要。
2. 企业主体与七维商业画像。
3. 业务匹配、合作要求、财务履约与风险核查。
4. 关键角色、商业假设和优先需求验证清单。
5. 切入方案、开发信首句、CTA及条件式后续行动。
6. 评分明细、证据覆盖与来源附录。

销售行动摘要模板：

| 结论 | 要写清的内容 |
| --- | --- |
| 是否值得跟进 | 开发优先级、匹配依据、重大障碍和不确定性；资料不足时暂不评级 |
| 从哪里切入 | 最有依据的产品/业务切入点及我方能力证据 |
| 接下来验证什么 | 最多3个优先问题，与详细清单一致 |
| 采取什么行动 | 联系角色、需要准备的资料、下一步及成立条件 |

摘要是研究结论的浓缩，不另造事实。仅完成阶段1时注明初步结论；阶段2–3或客户新答复完成后再更新，不声称尚未执行的行动已产生结果。

## 证据与质量检查

来源等级和结论可信度分开。A类来源包含官方登记、公司自述等不同子类型；公司官网不等于独立核实。转载不算独立交叉验证。重要结论与评分引用实际读过的来源，保留日期、范围及限制；争取覆盖有效来源类型，不为数量凑链接。

交付前检查：主体是否唯一；事实、假设和未知是否分开；价格是否可比；采购信号是否有效；我方能力是否有依据；角色权限是否得到确认；风险是否误归属；验证问题是否影响行动；摘要是否与证据一致；评分是否可复算。

## 安装与文件结构

通用分析方法不依赖固定行业。研究时只使用当前目标和当前产品线相关资料，不混用无关客户或品牌事实。

安装或更新前应在活动技能目录之外审查完整包及引用文件，再安装同一已审查版本。将包放入助手支持的技能目录，保持文件夹名为teco-target-customer-analyse；如未发现，按客户端机制刷新或开启新会话，不假设所有平台会即时重载。

- SKILL.md：触发条件、三阶段执行流程、七维画像及交付约定。
- references/assessment.md：证据、评分、付款与关键人分析规则。
- README.md：完整方法、示例、输出模板及使用说明。
- agents/openai.yaml：调用与显示元数据。
- COPYRIGHT、LICENSE：版权与MIT许可。

## 限制与验证状态

公开信息可能缺失或过时。本工具不替代正式信用审批、法律审查或人格测评，不自动联系客户、购买资料或发布研究结果。实际节省时间、客户回复和成交效果需要业务验证。

本次为流程与说明文档更新；结构、差异和静态安全检查不能证明真实客户调研结果准确，也不代表完成所有平台兼容性验证。未执行新的真实公司端到端调研。
